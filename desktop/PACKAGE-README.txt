第 1 部分

安装、升级与卸载指南

适用版本：FRP Panel 1.3.0。本文中的“安装目录”是安装程序所选择的根目录，不是其中的 desktop/app 子目录。

1. 安装条件

| 项目 | 要求及处理方式 |

| 操作系统 | Windows 10 或 Windows 11，x64 环境 |
| .NET | Microsoft .NET 8 Desktop Runtime x64；安装程序自动检测，缺少时联网安装 |
| 网页运行环境 | Microsoft Edge WebView2 Runtime；安装程序检测到缺少时调用官方安装程序 |
| Python | 安装包附带 Python 3.12.10，无须另外安装 |
| FRP 客户端 | 安装包附带 FRPC 0.71.0，无须另外下载 |
| 网络 | 下载软件、补装运行环境及在线更新需要访问相应官方下载服务；建立转发需要访问所配置的 FRPS |
| 权限 | 应用默认安装到当前用户目录；补装系统 .NET 运行环境时会请求 Windows 管理员权限 |

仅安装普通 .NET Runtime、x86 运行时，或者仅安装 .NET 9/10，不满足本程序的 .NET 8 桌面运行时要求。应用不需要 .NET SDK；SDK 只用于源码构建。

安装包约 17 MiB，程序文件展开后约 40 MiB。这是 1.3.0 的近似体积，不包含系统共享运行环境、WebView2 用户缓存、更新下载、配置备份和运行日志。实际占用随使用时间变化，应以文件夹属性为准。

2. 下载与文件校验

从 GitHub 正式发行页（https://github.com/Aliww2468/frp-panel/releases/latest） 下载安装程序。1.3.0 对应文件为 FRP-Panel-Setup-1.3.0-x64.exe；同页的 .exe.sha256 文件记录该安装程序的 SHA-256 摘要。

需要手工核对时，将两个文件放入同一文件夹，在该文件夹打开 PowerShell：

Get-FileHash -LiteralPath ./FRP-Panel-Setup-1.3.0-x64.exe -Algorithm SHA256
Get-Content -LiteralPath ./FRP-Panel-Setup-1.3.0-x64.exe.sha256

比较两处摘要，字母大小写不影响结果。摘要不一致时，重新从发行页下载并再次核对。SHA-256 用于检查文件完整性，不等同于 Windows 代码签名。

3. 首次安装

1. 如果其他目录已有 FRP Panel 正在运行，先从其托盘菜单选择“退出软件并停止转发”。仅关闭主窗口不会退出程序。
2. 双击安装程序，按安装向导选择目录及是否创建桌面快捷方式。
3. 安装程序检测运行环境。已有环境时直接继续；缺少 .NET 或 WebView2 时联网补装。
4. 如 Windows 提示需要管理员权限，完成系统运行环境安装所需的授权。取消授权或下载失败时，按安装器提示处理后重试。
5. 如 .NET 安装提示需要重新启动 Windows，重启后再次运行 FRP Panel 安装程序。
6. 安装完成后，从开始菜单或创建的桌面快捷方式启动。

默认安装目录为 %LOCALAPPDATA%\Programs\FrpPanel。可以将此路径粘贴到文件资源管理器地址栏。选择自定义目录时，应使用当前用户可写的位置，因为客户端配置、日志和备份保存在安装目录内。

首次启动会在配置文件不存在时生成空白配置及随机本机管理密码。安装包不包含开发者或其他用户的服务器地址、认证 Token、代理规则、日志及配置备份。已有配置文件不会因为启动而被重置。

4. 首次连接

已有服务商配置时，进入“连接配置”，选择“导入配置文件”，预览通过后应用。没有配置文件时，按照服务商提供的信息手工填写连接字段并保存。然后核对代理规则，回到概览选择“启动客户端”。

软件启动、配置保存和配置导入均不会自动开启转发。具体字段、导入限制及连通性检查见 用户操作手册（https://github.com/Aliww2468/frp-panel/blob/main/docs/user-guide.md）。

5. 在线更新

在线更新从 1.3.0 开始提供。更早版本需要先手工安装具有该功能的版本。

1. 保存当前表单中的修改。
2. 在主窗口右上角或托盘菜单选择“检查更新”。更新窗口显示当前软件版本。
3. 发现较新的正式版本后，阅读说明并选择“下载更新”。此阶段不会主动停止当前转发。
4. 等待下载及完整性校验完成，选择“安装并重启”。
5. 确认操作后，程序停止 FRPC 转发及面板后台，并等待相关进程退出，再交由安装程序更新文件。
6. 安装成功后软件重新打开。检查配置与规则，然后手动启动客户端恢复转发。

该功能仅检查本项目 GitHub Releases 的最新正式版本，不接受预发布版、同版本重装或降级。检查由用户手动发起，无须登录 GitHub，也不会在后台自动强制升级。

下载失败、超时或完整性校验失败时，可在更新窗口重试。GitHub 不可达或请求受到限制时，可稍后再试，或使用发行页下载的安装包手工升级。软件不提供第三方镜像切换入口。

升级保留已经写入磁盘的配置、日志和备份；未保存的表单内容不属于已保存配置。更新安装阶段会中断转发，应选择允许中断的时间操作。

在线更新适用于标准目录结构：安装目录/desktop/app/FrpPanel.exe。通过 --workspace 指向其他配置目录的分离部署，应使用手工升级方式。更新文件和安装日志保存在 %LOCALAPPDATA%\FrpPanel\<目录标识>\Updates\，其中目录标识由工作目录计算。

6. 手工覆盖升级

1. 保存配置，并备份 client/frpc.toml 及其引用的令牌、证书等文件。
2. 从托盘菜单退出旧版软件；如果单独启动了网页后台，也应先停止客户端，再结束对应后台。
3. 运行新版安装程序，确认安装目标是原来的安装根目录。
4. 完成安装后启动软件，检查连接配置、代理规则及版本，再手动恢复转发。

安装到新目录不会自动迁移旧目录的配置。若升级后出现空白状态，先核对快捷方式实际指向的目录，不要直接覆盖或删除旧配置。

从包含内置 .NET 的旧版升级时，安装程序按明确的旧运行库文件清单清理程序目录中的历史文件，保留 Python、配置、日志和备份。此操作不会卸载系统共享的 .NET。

7. 离线安装

提前在目标机器安装 .NET 8 Desktop Runtime x64 和 WebView2 Runtime，再复制 FRP Panel 安装程序进行安装。如果目标机器缺少运行环境，安装程序仍需联网补装，当前发行包不是包含全部系统运行环境的离线安装包。

离线条件只影响安装与更新方式。实际 FRP 转发仍需要目标机器能够连接所配置的服务器。

8. 卸载与保留数据

先从托盘菜单退出软件，再通过 Windows“已安装的应用”中的 FRP Panel 卸载入口操作。卸载会移除安装程序管理的应用文件、快捷方式及对应的当前用户自启动项。

运行后生成的配置、日志、备份以及本机缓存可能保留，便于重新安装或人工恢复。系统共享的 .NET 和 WebView2 不随本软件卸载。若需要清除个人数据，应在完成备份后，按 数据目录表（https://github.com/Aliww2468/frp-panel/blob/main/docs/user-guide.md#8-数据目录备份与恢复） 核对实际路径后自行处理。

9. 迁移到其他目录或计算机

在目标位置完成安装后，退出目标软件，再迁移 client/frpc.toml 和配置引用的外部文件。相对路径以目标 client 目录为基准，绝对路径需要按新机器实际位置修改。需要保留历史记录时，另行迁移日志及备份目录。

不要只复制 FrpPanel.exe。程序需要配套 DLL、Python、面板文件和 FRPC。外观缓存与当前用户自启动设置不随单独的客户端配置文件迁移；迁移完成后重新选择外观并设置自启动。

第 2 部分

FRP Panel 用户操作手册

适用版本：FRP Panel 1.3.0，附带 FRPC 0.71.0。本文说明已实现的操作及其影响。安装程序使用方法见 安装、升级与卸载指南（https://github.com/Aliww2468/frp-panel/blob/main/docs/installation.md）。

1. 软件用途与基本概念

FRP Panel 是在 Windows 本机运行的 FRP 客户端管理工具，用于导入连接配置、管理代理规则、启动或停止 FRPC、查看运行状态和日志。

| 名称 | 含义 |

| FRP Panel | 本软件，包括桌面窗口、本机面板后台及管理界面 |
| FRPC | 运行在本机的 FRP 客户端，负责建立到 FRPS 的连接并执行转发 |
| FRPS | 运行在远端服务器的 FRP 服务端，由服务商或服务器管理员维护 |
| 控制端口 | FRPC 连接 FRPS 使用的端口，不是对外提供游戏或应用服务的端口 |
| 本地地址与端口 | FRPC 需要访问的游戏服务器、网站或其他应用的监听地址与端口 |
| 远程端口 | TCP/UDP 代理在 FRPS 侧使用的对外访问端口 |
| 本机管理接口 | 面板读取 FRPC 状态、请求停止或重载的本地接口，默认端口为 7400 |
| 面板端口 | 桌面内嵌页面和浏览器访问面板后台使用的端口，默认为 17600 |

软件不会代为创建云服务器、购买服务、修改 FRPS 配置、放行云端安全组或启动本地游戏服务。这些条件需要由用户或服务商准备。

多数服务商要求先在其网站后台创建隧道并分配端口。面板中的“新建代理”只修改本机 FRPC 配置，不会向服务商申请新隧道或取得端口使用权限。

2. 界面与运行状态

左侧导航包含“概览”“代理规则”“运行日志”“连接配置”。概览集中显示客户端状态、代理数量、服务器信息、连接路径、规则列表及日志摘要。

| 显示内容 | 实际含义 |

| 客户端“待配置” | 尚未设置服务器地址，需要先添加或导入配置 |
| 客户端“连接中” | 面板启动的 FRPC 进程尚在运行，但面板尚未成功读取其管理接口 |
| 客户端“运行中” | 面板成功读取了 FRPC 管理接口；仍需检查各条代理的状态与日志 |
| 客户端“未连接” | 未读取到可用的 FRPC 管理接口，且面板未记录到仍在运行的客户端进程 |
| 代理“运行中” | FRPC 返回该条代理的运行状态为正常；公网实际可用性还需要从外部网络验证 |
| 同步失败提示 | 当前显示的数据可能来自上一次成功刷新，应先解决同步错误 |

客户端“运行中”不单独证明所有代理均已注册成功，也不证明外网访问一定畅通。检查时应结合代理状态、客户端日志及真实业务访问结果。

页面可见时约每 5 秒刷新一次状态，也可以点击“刷新状态”。正在编辑的连接表单不会被后台刷新直接覆盖；但修改后仍需点击保存才能写入配置。

3. 添加或导入连接配置

3.1 操作前准备

准备服务商提供的客户端配置文件，或服务器地址、控制端口、认证信息和代理参数。先确认本地业务能够通过其本地地址访问。

修改连接、应用导入或重置前，必须先停止客户端。如果本机管理端口仍被占用，面板也会拒绝修改，避免更改正在使用的连接配置。

3.2 导入 TOML 文件

1. 打开“连接配置”，选择“导入配置文件”。
2. 选择 UTF-8 编码的 .toml 客户端配置文件，大小不得超过 256 KiB，即 262144 字节。
3. 等待解析及 FRPC 校验完成，核对预览中的服务器地址、端口、代理数量、访问者数量和认证状态。
4. 确认应用导入。成功后，原配置自动备份，新配置写入 client/frpc.toml。
5. 核对规则，再手动启动客户端。

预览不会提交配置。应用导入采用整体替换方式：文件中的连接、认证、代理和访问者设置会取代原配置对应内容，不是将新代理追加到旧列表。

为保持面板能够管理客户端，导入时保留当前配置的 webServer 本机管理设置和 log 日志设置，忽略导入文件中这两个配置表的替换值。其他通过 FRPC 校验的高级配置随文件导入保留；这不表示界面提供了这些高级字段的编辑控件。

导入限制如下：

- 选择 FRPC 客户端配置，不要选择 FRPS 服务端配置；文件需要包含非空 serverAddr。
- 暂不支持 INI、YAML 或 JSON；不能仅修改文件扩展名来转换格式。
- 非空 includes 多文件引用需要事先合并成一个 TOML 文件。
- 导入只处理所选配置文本，不会自动复制 Token 文件、证书或其他引用文件。应预先将它们放到正确位置。
- 相对文件路径以安装目录的 client 文件夹为基准；指向其他机器的绝对路径需要调整。
- 如果预览后配置被其他程序修改，需要重新预览再提交。

3.3 手工填写连接

| 字段 | 填写要求 |

| 服务器地址 | FRPS 的 IP 或域名；不包含 http://、路径或端口 |
| 控制端口 | 服务商指定的 FRPS 连接端口，范围 1–65535；默认值 7000 不代表服务商一定使用该端口 |
| 用户标识 | 服务商要求的 user；不要求时可留空，最多 64 个字符 |
| Token 操作 | 可保留现有值、替换为新值或清除；已有 Token 不在界面回显 |
| TLS | 按服务端要求启用或关闭，不应凭连接失败随意更改 |
| 线路协议 | 选择服务端兼容的 v1 或 v2；应以服务商配置为准 |

保存连接时，现有代理及未涉及的高级设置会保留。连接配置保存会重新生成 TOML 排版，原注释可从自动备份中查阅。

对于已有 OIDC 或 Token 文件引用的高级配置，“保留”维持原认证配置；选择“替换”或“清除”会切换为 Token 认证并移除原 OIDC、Token 文件引用。因此，使用高级认证时应先确认所需认证方式。

3.4 重置连接与代理

“重置连接与代理”需要二次确认。确认后，服务器地址、用户标识、认证、代理、访问者及其他未保留的高级设置会清空，本机管理接口设置保留，日志切换到新文件，TLS 和线路协议恢复为默认值。

重置不是删除历史文件。原配置备份、旧日志和外部令牌文件仍保留在本机，但新空白配置不再引用旧连接和令牌。重置后需要重新添加连接，才能启动客户端。

4. 管理代理规则

4.1 新建代理

先在服务商后台取得有效的隧道信息，再在“代理规则”或概览的规则区选择“新建代理”。自行维护 FRPS 的用户也需要确保服务端允许使用目标端口。

| 字段 | 说明 |

| 名称 | 与服务商要求一致；本配置内唯一，长度 1–64，可使用字母、数字、中文、下划线、横线和点 |
| 协议 | 当前表单支持 TCP 或 UDP；应与本地服务及服务商分配的协议一致 |
| 本地地址 | 业务与 FRPC 在同一机器时通常使用 127.0.0.1；其他机器使用 FRPC 能访问的对应地址 |
| 本地端口 | 本地业务实际监听的端口，范围 1–65535 |
| 远程端口 | 服务商分配或自建 FRPS 允许使用的对外端口，范围 1–65535 |

例如，本地 TCP 服务监听 127.0.0.1:25565，服务商分配远程 TCP 端口 30001 时，填写本地端口 25565、远程端口 30001。示例数字仅用于说明字段关系，不能替代服务商实际分配信息。

同一配置不能使用重复的代理名称，也不能让两条相同协议的代理使用同一远程端口。

4.2 编辑、删除及生效时机

选择规则右侧编辑按钮可修改 TCP/UDP 基础字段。面板尽量保留该代理的高级字段和配置中的其他内容；特殊 TOML 排版无法安全定位时，会要求通过文件编辑。

删除需要确认，删除的是本机配置中的规则，不会代为删除服务商后台的隧道。对于已导入的非 TCP/UDP 代理，界面禁用基础编辑，但列表仍可能提供删除入口，操作前应核对类型与名称。

每次规则修改通过校验后均会保存并备份旧配置。如果 FRPC 管理接口可用，面板会请求热重载；如果不可用，新配置在下次启动时生效。热重载失败时，配置仍已保存，应按提示重启客户端并检查规则状态。修改或删除正在使用的代理可能中断该条转发。

4.3 搜索、筛选与复制地址

规则列表支持按名称或端口搜索，并按全部、TCP、UDP 筛选。复制按钮生成“服务器地址:远程端口”，便于使用 TCP/UDP 代理。

导入的 HTTP、HTTPS、访问者或其他高级模式可能使用自定义域名或其他访问方式，列表中的基础地址拼接不能作为这类模式的完整访问说明。相关高级设置应结合原配置及 FRP 官方文档处理。

5. 启动、停止与后台运行

5.1 启动和连通性确认

确认本地业务已启动、连接配置已保存且代理信息正确后，在概览点击“启动客户端”。启动请求成功只表示已发起运行，随后需要等待状态刷新。

建议按以下顺序验证：本地业务访问正常；客户端管理接口可用；代理未报告错误；从另一网络使用分配的公网地址进行真实业务访问。游戏服务应实际进入服务器验证，不能只以端口检测结果代替业务测试。

5.2 不同退出操作的区别

| 操作 | 桌面与后台 | FRPC 转发 |

| 最小化或关闭主窗口 | 隐藏至系统托盘，继续运行 | 已启动的转发继续运行 |
| 双击托盘图标 | 恢复原主窗口 | 不改变转发状态 |
| 停止客户端 | 面板继续运行 | 停止该客户端的所有转发，本地业务进程不受影响 |
| 托盘“退出软件并停止转发” | 停止后台并退出桌面 | 先停止转发；停止失败会提示处理 |
| Windows 睡眠、关机或注销 | 不能作为持续在线后台运行 | 无法保证持续转发，恢复后应重新检查 |

5.3 重复启动检测

同一 Windows 会话只允许一个 FRP Panel 桌面实例，即使从不同安装目录启动也会检测。检测到原实例后，新启动显示“软件已在运行”的提示；关闭提示后，本次启动退出，原实例继续工作。

请通过系统托盘恢复原窗口，不要反复点击快捷方式。该限制针对桌面实例，不代表操作系统中只能出现一个相关进程：Python 后台、FRPC 和 WebView2 子进程属于正常组成部分。单独通过命令行启动的网页后台不受桌面互斥锁直接限制。

旧版程序自身可能尚无完整检测逻辑。若保留多个安装目录，应统一更新常用入口，避免随后从旧版可执行文件启动。

5.4 开机自启动

自启动默认关闭，可在托盘菜单中开启。开启后，在当前 Windows 用户登录时启动软件并驻留托盘，仍需手动启动 FRPC 转发。

这是用户登录会话中的后台程序，不是 Windows 系统服务。移动目录后应重新设置自启动；自定义端口参数目前不会由托盘自启动设置保存，登录后使用默认面板端口。

6. 运行日志

“运行日志”支持关键字搜索和文本导出。面板读取当前 log.to 文件尾部最多 64 KiB，再取其中最近 100 行；概览只显示最近日志摘要。

导出内容是最近一次加载到页面的日志数据，不是整个历史日志文件，也不因当前搜索条件而只导出筛选结果。需要完整记录时，到 client/logs 查阅实际文件；配置自定义日志路径时，以 log.to 为准。

FRPC 启动输出另存于 client/logs/panel-launch.log，可用于排查正式日志尚未产生时的启动错误。面板会对已知凭据进行脱敏，但原始配置、日志和备份仍可能包含敏感信息，对外提交前应人工检查。

7. 外观与软件更新

在右上角“外观”选择简约浅色、午夜深色、暖砂米色或雾蓝灰，选择后立即应用并保存在本机。桌面版与独立浏览器各自使用自己的浏览器存储。

Windows 11 支持标题栏颜色跟随主题及隐藏外框描边；Windows 10 的标题栏效果受系统支持范围限制。清除浏览器缓存、迁移工作目录或更换 Windows 用户后，可能需要重新选择风格。

右上角及托盘的“检查更新”只在桌面版提供。更新步骤及中断时机见 在线更新说明（https://github.com/Aliww2468/frp-panel/blob/main/docs/installation.md#5-在线更新）。界面中的 FRPC 版本与更新窗口中的 FRP Panel 软件版本是不同组件的版本号。

8. 数据目录、备份与恢复

下列相对路径均以安装根目录为基准。

| 路径 | 内容 |

| desktop/app/FrpPanel.exe | 桌面主程序 |
| desktop/app/python/ | 随程序附带的 Python 运行文件 |
| client/frpc.exe | 执行实际转发的 FRPC |
| client/frpc.toml | 当前客户端配置，可能包含认证信息 |
| client/logs/ | 默认日志目录及客户端启动输出 |
| panel/backups/ | 面板修改前保存的完整配置备份 |
| %LOCALAPPDATA%/FrpPanel/<目录标识>/ | 桌面日志、主题记录、WebView2 缓存及更新下载 |

配置备份发生在面板通过校验并准备写入修改时，文件名包含时间与随机后缀。通过文本编辑器直接修改文件不会自动触发面板备份。配置备份只包含 TOML 本身，不自动包含外部令牌、证书和其他依赖文件；备份目录也没有自动轮换清理功能。

恢复已有备份时：

1. 停止客户端并退出桌面软件，避免写入冲突。
2. 另存当前配置及其外部依赖文件，保留恢复前状态。
3. 从 panel/backups 选择所需备份，复制到 client/frpc.toml。如果不需要恢复本机管理和日志设置，也可以重新启动面板后使用导入入口恢复连接与代理。
4. 检查备份引用的文件仍存在、相对路径与目标目录一致。
5. 启动面板并检查配置，再手动启动客户端，验证代理与外网访问。

若只是退出或重新安装，通常不需要重置连接。遇到异常时先参考 故障排查指南（https://github.com/Aliww2468/frp-panel/blob/main/docs/troubleshooting.md），避免不必要地覆盖现有配置。

第 3 部分

FRP Panel 故障排查指南

适用版本：FRP Panel 1.3.0。处理问题前先确认是安装、桌面启动、配置校验、FRPC 连接还是实际转发失败。不同阶段使用的端口、日志与运行环境不同。

1. 安装提示缺少 .NET 或 WebView2

安装程序会检测 .NET 8 Desktop Runtime x64 及 WebView2。已有普通 .NET Runtime、x86 环境或其他 .NET 主版本，仍可能需要补装指定的桌面运行时。

先检查网络和安装提示。若拒绝了 .NET 安装的管理员授权，需重新运行安装程序并完成授权；如提示需要重启，先重启 Windows，再继续安装。离线机器应预先安装上述运行环境。不要通过删除系统共享 .NET 来排查问题。

如手工检查 .NET，可运行 dotnet --list-runtimes，观察是否同时存在 x64 安装位置下的 Microsoft.WindowsDesktop.App 8.0.x 和 Microsoft.NETCore.App 8.0.x。命令不在 PATH 时，应使用实际 x64 dotnet.exe 路径；命令不可用本身不能直接证明运行环境未安装。

2. 提示软件已经运行，但未看到窗口

主窗口关闭或最小化后会进入托盘。展开任务栏通知区域的隐藏图标，找到 FRP Panel 并双击，即可恢复窗口。重复启动提示关闭后，新启动进程退出，原程序不会自动关闭。

仍无法定位时，在任务管理器核对 FrpPanel.exe 的运行路径，确认是否来自旧安装目录。需要更换目录运行时，应先通过原程序托盘菜单退出，再启动目标版本。

Python、FRPC 和多个 WebView2 子进程并不等于打开了多个面板窗口。不要仅因进程数量大于一就批量结束这些进程。

3. 面板启动失败、端口占用或窗口无内容

默认面板端口是 17600，默认 FRPC 管理端口是 7400。先确认没有旧目录桌面、独立网页后台或其他程序占用对应端口，再检查 client/frpc.toml 是否可解析，以及应用文件是否完整。

可以用以下只读命令检查监听端口与进程编号：

Get-NetTCPConnection -State Listen -LocalPort 17600,7400 -ErrorAction SilentlyContinue |
    Select-Object LocalAddress,LocalPort,OwningProcess

根据查到的编号进一步核对进程路径，确认归属后再通过该程序的正常退出入口处理，不应直接结束所有 Python 或 FRPC 进程。

桌面错误日志为 %LOCALAPPDATA%\FrpPanel\<目录标识>\desktop.log。缺少 Python 文件通常表示只复制了 EXE 或应用目录不完整；安装版可覆盖安装修复，源码版可重新构建。配置格式错误应先备份并修复配置。

确认后台可用后，仍出现空白窗口时，检查 WebView2 Runtime 是否已安装及当前用户是否具有缓存目录写入权限。桌面网页入口是本机 HTTP 服务，不需要将其暴露到公网。

4. 无法导入配置

| 提示或现象 | 检查方法 |

| 文件格式或大小不符 | 确认是真正的 UTF-8 TOML，扩展名为 .toml，且不超过 256 KiB |
| 缺少 serverAddr | 确认选择 FRPC 客户端文件，而不是 FRPS 服务端文件 |
| 引用了其他配置文件 | 将非空 includes 引用合并为一个 TOML，再导入 |
| HTTP/HTTPS 代理缺少访问域名 | 按服务商支持的方式填写 customDomains 或 subdomain；没有域名且希望使用公网 IP:端口时，在服务商后台创建 TCP 隧道并重新导出配置 |
| FRP 校验失败 | 检查字段、重复名称及引用文件是否适用于附带的 FRPC 0.71.0；参阅服务商原始配置 |
| 运行中无法应用 | 先停止客户端，确认管理端口不再被占用 |
| 预览后无法提交 | 原配置可能被外部修改，重新选择文件、预览并提交 |
| 导入后管理接口或日志路径未变化 | 属于预期行为，导入保留当前 webServer 和 log 配置 |

Token 文件和证书不会随 TOML 自动复制。相对路径以 client 为基准。校验失败时不要为了绕过检查删除自己不了解的认证或 TLS 配置，应向服务商确认兼容配置。

5. 配置保存时提示发生变化

面板使用配置版本校验防止覆盖其他窗口或编辑器刚写入的内容。先保存一份尚未提交的输入供对照，再刷新页面，检查磁盘上的最新配置，然后重新进行修改。该提示不代表配置丢失。

如果提示“当前配置使用了特殊 TOML 格式”，应先备份，再通过文件编辑所需字段；不要反复提交同一表单。手工编辑后可以运行 FRPC 的 verify 命令检查，具体命令见 客户端目录说明（https://github.com/Aliww2468/frp-panel/blob/main/client/README.md）。

6. 客户端启动后一直连接中或立即退出

依次检查服务器地址与控制端口、认证方式、用户标识、TLS 与线路协议是否和服务商要求一致。然后查阅运行日志；正式日志尚未产生时，检查 client/logs/panel-launch.log。

还应核对 FRPC 管理端口是否被其他客户端占用、webServer 是否绑定本机回环地址及管理认证是否匹配。面板不能成功读取管理接口时，不能仅据界面“未连接”判定所有外部启动的客户端均已停止。

面板只负责启动 FRPC，本地游戏或应用服务需要另行启动。修改连接设置前先停止客户端，修改后重新启动并观察新的日志。

7. 代理保存成功，但公网无法访问

“保存成功”表示配置已经写入并通过本地校验；它不表示服务商已授予端口权限，也不表示本地服务可用。

1. 在本地直接访问业务，确认地址、端口和 TCP/UDP 类型正确。
2. 检查服务商后台是否已创建对应隧道，名称及远程端口是否一致，端口是否已被占用。
3. 检查该条代理的状态和错误信息，而非只看客户端总状态。
4. 如提示热重载失败，停止并重新启动客户端，使已保存配置重新加载。
5. 由服务器管理员检查 FRPS 端口限制、防火墙与云端安全组。
6. 从另一网络进行实际业务测试。对于 HTTP/HTTPS 等高级配置，使用原配置要求的域名和访问方式。

多数服务商不支持客户端自行创建隧道，应以服务商后台分配的信息为准。

8. 日志为空、内容不全或导出数量较少

未启动 FRPC、当前日志尚无新内容、日志输出到控制台，或配置使用其他 log.to 路径，都可能导致页面暂无日志。

页面只读取当前日志文件尾部最多 64 KiB 中的最近 100 行，导出同样是已加载的最近日志，不包含整个历史目录。完整日志应从实际文件读取。重置连接后使用新的日志文件，旧日志仍留在本机。

9. 检查更新失败或没有发现更新

检查更新需要能访问 GitHub API 和发行附件下载服务。网络故障、请求限额、发布附件缺失、摘要不匹配或超时都会使更新失败，可稍后重试或手工下载正式安装包。

同版本、较旧版本及预发布版不会被作为可安装更新。仅更新 GitHub 文档而未发布更高软件版本时，软件仍会显示已是最新版本。1.3.0 之前的版本没有在线更新入口；独立浏览器网页也不显示桌面更新按钮。

下载与检查阶段不会主动停止转发。确认“安装并重启”后才开始停止后台；若安装准备失败，先检查面板和客户端是否仍在运行，再按提示恢复。软件不会自动恢复转发。

安装日志通常位于 %LOCALAPPDATA%\FrpPanel\<目录标识>\Updates\<下载标识>\install.log。自定义可执行文件与工作目录分离的部署，应手工覆盖升级到正确目录。

10. 更新后配置为空、版本未变化或外观恢复默认

先检查快捷方式指向的真实程序路径。源码目录、默认安装目录和其他测试目录各自可能有独立配置；启动另一目录不等于原配置被清空。

查看更新窗口的 FRP Panel 版本，不要将页面中的 FRPC 0.71.0 当作桌面软件版本。若仍启动旧路径，使用新版安装目录的快捷方式。需要迁移配置时，参考 迁移说明（https://github.com/Aliww2468/frp-panel/blob/main/docs/installation.md#9-迁移到其他目录或计算机）。

外观保存在本机浏览器缓存和目录对应的桌面状态中。更换目录、Windows 用户或清理缓存后可能恢复默认，可重新选择主题。

11. 开机自启动后没有转发

这是当前设计行为。自启动只在当前用户登录时将面板启动到托盘，不会自动启动 FRPC。请恢复窗口或使用托盘菜单手动启动客户端。

软件不是 Windows 系统服务；用户注销、电脑睡眠或关机时不能维持持续转发。自定义端口未被托盘自启动设置保存，默认仍使用 17600，需留意该端口的占用情况。

12. 提交问题时提供的信息

通过 GitHub Issues（https://github.com/Aliww2468/frp-panel/issues） 提交问题时，请注明 FRP Panel 版本、Windows 版本、安装版或源码运行方式、复现步骤、预期结果、实际提示及相关日志片段。涉及更新时附上安装日志中的失败阶段。

不要直接上传完整 client 目录或配置备份。先移除 Token、密码、证书私钥及不希望公开的服务器地址。页面脱敏不能替代对原始文件的人工检查。
