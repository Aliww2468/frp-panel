# 网页面板与本机后台说明

本文说明 FRP Panel 1.3.0 的独立网页入口和 Python 后台。普通界面操作见 [用户操作手册](../docs/user-guide.md)，桌面窗口及安装器见 [桌面说明](../desktop/README.md)。

## 1. 运行条件

后台使用 Python 3.11 或更新版本及标准库，不需要额外安装第三方 Python 依赖。默认读取项目根目录的 `client/frpc.toml`，通过同目录的 `frpc.exe` 校验配置并启动转发。

从源码运行前，按 [客户端说明](../client/README.md) 准备 FRPC 0.71.0。首次启动时只在配置不存在的情况下生成空白配置；已有文件不覆盖。

## 2. 独立网页启动方式

在项目根目录运行：

```powershell
python ./panel/server.py
```

随后在本机浏览器打开 `http://127.0.0.1:17600`。命令保持运行期间，后台提供页面和接口。

已构建桌面目录版本时，也可以明确使用其附带的 Python：

```powershell
./desktop/app/python/python.exe ./panel/server.py
```

根目录“启动面板.cmd”调用 `panel/start-panel.ps1`。该启动器先尝试复用默认端口上已有的面板，再选择 Python 并启动隐藏后台及浏览器。Python 查找顺序为本机 Codex 运行环境的固定路径，然后是 PATH 中可用的 `python.exe`；它当前不会主动搜索 `desktop/app/python`。没有前两种环境时，请使用上面的显式命令。

启动器以默认端口上的响应识别已有面板，不进行桌面入口同等的工作目录身份核对。多目录开发时应明确使用所需后台，不要将浏览器复用成功视为已切换到当前目录。

## 3. 参数、目录和端口

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--port` | `17600` | 面板 HTTP 监听端口，绑定地址固定为 `127.0.0.1` |
| `--client-dir` | 项目根目录的 `client` | 配置、FRPC 可执行文件和相对引用文件的基准目录 |

示例使用同一客户端目录和另一个空闲面板端口：

```powershell
python ./panel/server.py --port 17601 --client-dir ./client
```

使用命令前先停止管理相同配置的其他后台。`--port` 修改的是面板页面端口，不会修改 FRPS 控制端口，也不会修改 `webServer.port` 中的 FRPC 管理端口。

备份目录固定为当前 `server.py` 所在目录的 `backups`，不会随 `--client-dir` 自动移动。独立网页后台不使用桌面单实例互斥锁，应由使用者避免多个后台同时操作同一客户端。

## 4. 启动、停止和退出

启动后台或打开浏览器不自动启动 FRPC。通过概览“启动客户端”发出请求后，后台先校验配置，再以 `client` 为工作目录运行 FRPC，并把启动输出追加到 `client/logs/panel-launch.log`。

关闭浏览器标签页不会停止后台或 FRPC。手工运行 `server.py` 时，正确的停止顺序为：在页面停止客户端，确认转发停止，再在运行后台的终端按 Ctrl+C。仅按 Ctrl+C 结束后台不会自动停止独立运行的 FRPC。

通过隐藏启动器启动的后台没有前台终端。需要结束时，先在页面停止客户端，再核对实际后台进程及路径后结束该后台；不要批量终止其他 Python 进程。日常驻留和退出管理建议使用桌面托盘入口。

桌面版使用专门退出接口停止 FRPC、等待退出并结束后台。如果客户端未能及时停止，会返回错误，由桌面提示处理。

## 5. 配置修改机制

### 5.1 校验、备份和版本检查

配置提交先解析 TOML，并调用本地 `frpc.exe verify` 校验候选文件。校验通过后，再次检查当前文件是否被外部修改，备份原配置，最后以原子替换方式提交候选文件。

页面提交连接或代理修改时携带配置修订标识。修订不一致会拒绝覆盖并要求刷新，避免无意覆盖外部编辑。进程内部使用锁串行处理写入，但此机制不是跨多个独立后台的分布式锁。

自动备份只保存原始 TOML，不复制外部令牌或证书，也不自动清理历史备份。备份包含原始凭据，不应上传到公共仓库。

### 5.2 不同操作的影响

| 操作 | 运行前提 | 保存内容和生效方式 |
| --- | --- | --- |
| 保存连接 | 客户端停止且管理端口空闲 | 更新连接字段，保留代理与其他未涉及设置；下次启动生效 |
| 导入配置预览 | 可先进行校验 | 不提交配置，返回摘要和修订标识 |
| 应用导入 | 客户端停止且管理端口空闲 | 替换导入内容，保留当前管理和日志设置；不自动启动 |
| 重置连接与代理 | 客户端停止且管理端口空闲 | 生成空白连接状态，保留本机管理设置并切换新日志文件 |
| 新建、编辑、删除代理 | 已配置服务器地址 | 保存后在管理接口可用时请求热重载，否则下次启动生效 |

热重载失败不会回滚已经保存的配置，应按提示重新加载或重启客户端。连接保存及导入会重新序列化 TOML，原注释和排版可从备份中找回。代理基础编辑则尽量保留其他字段及高级子表；无法定位的特殊 TOML 格式会拒绝编辑。

### 5.3 功能边界

界面编辑 TCP/UDP 基础字段，不能代替所有 FRP 高级配置的文本编辑。导入支持通过 FRPC 校验的高级内容及访问者，但没有完整的访问者管理界面。导入文件需为 UTF-8 TOML、最多 256 KiB，非空 `includes` 需要事先合并。

面板复制的基础访问地址面向 TCP/UDP。高级 HTTP/HTTPS 等模式需要依据原配置使用域名或其他访问方式。

## 6. 状态与日志语义

后台 `connected` 表示成功读取了 FRPC 本机管理接口，不直接证明服务器登录或全部代理正常。`processRunning` 只表示后台记录的 FRPC 子进程仍存活，不能用于枚举所有外部启动的 FRPC。每条代理的状态和错误来自 FRPC 管理接口返回值。

日志接口读取 `log.to` 指向的实际文件尾部最多 64 KiB，再返回最近 100 行。页面日志搜索发生在已加载内容中，导出的是本次加载的日志集合，而非全部历史记录。日志输出到控制台或文件尚未创建时可能返回空列表。

错误和日志会对已知 Token、管理密码及匹配的凭据文本进行脱敏，但原始文件仍应按敏感数据处理，不能承诺覆盖任意第三方日志中的所有秘密。

## 7. 本机接口概览

这些接口用于本机页面和桌面程序之间通信，不是面向公网的服务管理 API，也没有远程多用户登录系统。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 返回应用标识、工作目录、后台 PID 和桌面接口版本 |
| `GET /api/state` | 返回配置修订、页面会话令牌、连接摘要和代理状态；不回显保存的认证 Token |
| `GET /api/logs` | 返回最近日志行 |
| `POST /api/connection/save` | 保存连接字段 |
| `POST /api/connection/reset` | 重置连接与代理 |
| `POST /api/connection/import-preview` | 校验导入文件并生成摘要 |
| `POST /api/connection/import` | 提交已确认的导入内容 |
| `POST /api/proxy/save` | 新增或编辑代理基础字段 |
| `POST /api/proxy/delete` | 删除指定代理 |
| `POST /api/control/start` | 校验并启动客户端 |
| `POST /api/control/stop` | 请求停止客户端 |
| `POST /api/control/reload` | 校验并请求重载客户端配置 |
| `POST /api/desktop/exit` | 停止客户端，确认退出后关闭后台 |

后台绑定回环地址，验证请求的 Host 和存在时的 Origin；写入请求还需要匹配当前后台会话的 `X-Panel-Token`。后台重启后旧会话令牌失效，需要刷新页面。面板会话令牌与连接 FRPS 使用的认证 Token 是不同用途的值。

静态页面采用明确的文件路径白名单，默认只提供首页、脚本、样式和图标。响应关闭缓存并设置内容安全策略。不要通过反向代理或端口转发公开这个本机管理入口。

## 8. 开发验证

```powershell
python -m unittest discover -s panel/tests -v
```

测试使用独立临时配置。`test_first_run.py` 检查初始配置保护；`test_import.py` 检查导入、校验及备份；`test_panel.py` 检查字段修改、认证和可用时的 FRP 集成行为；`test_desktop_api.py` 检查身份及授权退出接口。

完整集成测试依赖可执行的测试 FRPS，缺少时会明确跳过。发布记录应区分静态检查、后端测试、实际桌面运行及外网转发，不应把跳过的用例写成通过。
